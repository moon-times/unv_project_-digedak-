# 🎤 딕으닥 — 흥얼거림을 밴드곡으로

> 허밍 한 소절을 녹음하면 음표로 바꾸고, AI가 키 · 코드를 분석해 밴드 반주를 붙이고, 간단히 편집해서 완성곡으로 내보내는 웹 서비스

---

## 1. 프로젝트 소개

### 배경
악기를 다루지 못하거나 작곡 도구(DAW)가 어려운 사람도 머릿속 멜로디를 곡으로 만들고 싶어 합니다. 하지만 기존 DAW는 진입 장벽이 높고, AI 음악 생성 서비스는 사용자의 멜로디를 반영하지 못하는 경우가 많습니다.

### 목표
1. 허밍 한 소절에서 반주가 붙은 곡까지, **누구나 몇 분 안에** 완성할 수 있는 웹 서비스 구축
2. **사용자의 멜로디를 중심에 두고**, AI는 분석 · 설명으로 돕는 창작 도구 구현 — 결과를 편집 가능한 음표 데이터로 유지

### 핵심 타깃
- 악기를 못 다루거나 DAW(작곡 툴)가 어려운 사람
- 갑자기 떠오른 멜로디를 간단하게 구현하고 싶은 사람 (작곡 능력이 있어도 떠오른 순간 바로 만들어 저장해 두고 싶은 사람 포함)

### 핵심 사용자 흐름
```
🎤 허밍 녹음
  → 🎼 음표 추출 + 피아노롤 보정
  → 🤖 AI 분석 (키 / 코드 진행 / 장르 스타일)
  → 🥁 밴드 반주 생성 (드럼 / 베이스 / 피아노)
  → 🎚️ 믹싱 · 편집
  → 💾 WAV 내보내기 · 프로젝트 저장
```

## 2. 기능 명세

### 필수 기능 (MVP)

| 구분 | 기능 | 설명 |
|---|---|---|
| 녹음 | 마이크 녹음 | 브라우저에서 최대 30초 녹음, 메트로놈(카운트인) 제공 |
| 음표 변환 | 피치 검출 | 단선율 피치 검출 → MIDI 음표 변환 |
| 음표 변환 | 퀀타이즈 | 박자(16분음표 단위)와 음정(반음 단위) 보정 |
| 음표 변환 | 피아노롤 편집 | 음표 추가 / 삭제 / 이동 / 길이 조절 |
| 분석 | AI 분석 | 규칙 엔진이 키, 코드 진행, 스타일, 기본 설명을 계산해 JSON으로 반환 |
| AI | 설명 다듬기 | LLM이 규칙 엔진의 기본 설명 문장을 자연스럽게 다듬음 (실패하거나 한도를 넘으면 기본 설명 유지) |
| 반주 | 템플릿 반주 | 장르 2~3개(예: 팝, 발라드, 록)의 드럼·베이스·피아노 패턴 |
| 재생 | 통합 재생 | 멜로디 + 반주 동시 재생, BPM 변경 |
| 편집 | 트랙 믹서 | 트랙별 볼륨, 뮤트, 솔로 |
| 내보내기 | WAV 렌더링 | 오프라인 렌더링 후 다운로드 |
| 계정 | 게스트 체험 | 로그인 없이 스튜디오 이용, 내보내기 · 저장할 때 로그인하면 작업을 그대로 이어서 저장 |
| 계정 | 로그인 / 저장 | 이메일 · GitHub · Google 로그인, 프로젝트 저장(자동 저장) · 불러오기 · 목록 · 삭제 |

### 선택 기능 (여유 시)

- 원본 녹음 파형 표시, 구간 자르기, 페이드 인/아웃
- 트랙 이펙트 (리버브, EQ, 컴프레서)
- 악보(오선보) 표시
- 코드 진행 수동 수정
- AI 재추천 ("더 밝게 / 더 슬프게" — LLM 제안 코드는 규칙 엔진 점수로 검사)
- 프로젝트 공유 링크 (읽기 전용 페이지)
- 내보낸 WAV를 Storage에 보관
- 장르 추가, 섹션 구성(인트로 / 벌스 / 코러스)

### 범위에서 제외

- 오디오 생성형 AI(MusicGen 등) — 비용, 속도, Vercel 실행 시간 제한 문제
- 가사 생성 및 보컬 합성
- 다중 사용자 실시간 공동 편집

### 화면 구성
- **페이지**: 랜딩 `/` → 인증(이메일 · GitHub · Google) → 내 프로젝트 `/projects` → 스튜디오 `/studio/[id]`, (선택) 공유 페이지 `/share/[id]`
- **스튜디오 레이아웃 — 고정 타임라인 + 단계별 도구 패널**
  - 가운데: 항상 보이는 타임라인 (코드 레인 · 멜로디 피아노롤 · 드럼 · 베이스 · 건반 줄, 재생 위치)
  - 위: 진행 바 4단계 (① 녹음 → ② 보정 · AI 분석 → ③ 반주 → ④ 믹싱), 단계에 따라 오른쪽 도구 패널만 바뀜
  - 아래: 재생 바 (재생 · 정지, BPM, 재생 시간)
  - 처음에는 [다음 단계] 안내를 따라가고(녹음 전에는 뒤 단계 비활성), 첫 완성 후에는 진행 바를 탭처럼 자유롭게 이동
- **내보내기 · 저장**: 단계가 아니라 상단 [내보내기] 버튼의 팝업창. 게스트는 여기서 로그인으로 이어짐
- **게스트 범위**: 녹음 ~ 믹싱까지 이용 가능, WAV 다운로드와 프로젝트 저장은 회원 전용. 게스트 작업은 로그인 전까지 브라우저에만 있고, 로그인하면 `projects`에 저장된 뒤 스튜디오로 복귀
- 화면 목업: `docs/design/딕으닥 화면 목업.html`

## 4. 시스템 아키텍처

```
┌─────────────────────── 브라우저 ───────────────────────┐
│  녹음(Web Audio) → 피치 검출(Pitchy) → 퀀타이즈          │
│  분석 엔진(규칙 기반: 키 · 코드 진행 · 스타일)            │
│  고정 타임라인(피아노롤 · 코드 레인 · 반주 줄) + 도구 패널 │
│  반주 생성 엔진(템플릿) → Tone.js 재생 · 렌더링           │
│  Zustand: Song State                                    │
└──────┬───────────────────────┬──────────────────────────┘
       │ ① 분석 결과 + 요청      │ ③ 오디오 파일 직접 업로드
       ▼                       ▼
┌──────────────────┐   ┌──────────────────────────────┐
│ Vercel           │   │ Supabase                     │
│ /api/analyze     │   │ - Auth                       │
│  (LLM 보조 호출,  │   │ - projects 테이블 (JSON)      │
│   API 키 보호)    │   │ - Storage (녹음 / WAV)        │
└──────┬───────────┘   └──────────────────────────────┘
       │ ② 다듬은 설명 · 재추천 코드 JSON
       ▼
   LLM API
```

**설계 원칙 (하이브리드: 규칙 엔진이 주연, LLM은 보조)**
1. **오디오 처리는 모두 브라우저에서** — Vercel 요청 크기(약 4.5MB)와 실행 시간 제한을 피합니다.
2. **AI 분석의 기본 계산은 브라우저의 규칙 엔진이** — 외부 API 없이 음악 이론으로 계산합니다. 결과는 `/api/analyze`와 같은 JSON 형식이라 다른 부분에는 영향이 없습니다.
   - 키: Krumhansl–Schmuckler 알고리즘 (음별 사용 길이를 장·단조 24개 표준 분포와 비교)
   - 코드 진행: 마디별 후보 코드 점수(멜로디 음과 구성음 일치, 강박·길이 가중) + 코드 전환의 자연스러움 → Viterbi로 전체 최적 진행 선택
   - 스타일: BPM · 장/단조 · 음 밀도 규칙 (사용자가 장르를 직접 바꿀 수 있음)
   - 기본 설명: 분석 근거로 문장 틀을 채움 (예: "C·E·G가 많이 쓰여 C장조로 판단")
3. **LLM은 보조 역할만** — 설명 문장 다듬기와, 선택 기능인 "더 밝게 / 더 슬프게" 재추천 같은 자연어 요청에만 호출합니다. LLM이 실패하거나 한도를 넘어도 곡 제작 흐름은 그대로 동작하고, LLM이 제안한 코드는 규칙 엔진 점수로 검사해 멜로디와 크게 부딪히면 버립니다.
4. **서버는 LLM 호출 전용** — API 키를 숨기는 역할만 합니다.
5. **반주 음표는 "코드"가 생성** — 실제 반주 음표는 장르 템플릿 엔진이 만듭니다. 결과의 안정성과 박자 정확도를 보장하기 위함입니다.
6. **하나의 Song State** — 모든 화면이 같은 JSON을 읽고 수정합니다. 저장도 이 JSON 하나면 됩니다.

## 5. 데이터 모델

### Song State (TypeScript)

```ts
type Note = {
  pitch: number;      // MIDI 번호 (60 = C4)
  start: number;      // 시작 위치 (16분음표 단위 step)
  duration: number;   // 길이 (step)
  velocity: number;   // 0 ~ 1
};

type Chord = {
  symbol: string;     // "Cmaj7", "Am" 등
  start: number;      // step
  duration: number;   // step
};

type Track = {
  id: 'melody' | 'drums' | 'bass' | 'keys';
  instrument: string;
  volume: number;     // dB
  muted: boolean;
  solo: boolean;
  effects?: { reverb?: number; eqLow?: number; eqHigh?: number };
};

type SongState = {
  version: 1;
  title: string;
  bpm: number;
  key: string;            // "C major"
  timeSignature: [number, number];
  style: 'pop' | 'ballad' | 'rock';
  melody: Note[];
  chords: Chord[];
  explanation?: string;   // AI 분석 설명 (규칙 엔진 기본 설명 또는 LLM이 다듬은 설명)
  accompaniment?: { drums: Note[]; bass: Note[]; keys: Note[] };  // 반주 엔진 결과 (타임라인 반주 줄 표시용)
  tracks: Track[];
  recording?: { path: string; trimStart?: number; trimEnd?: number };
};
```

### 분석 결과 스키마 (규칙 엔진 · `/api/analyze` 공통)

```json
{
  "key": "C major",
  "chords": [{ "symbol": "C", "start": 0, "duration": 16 }],
  "recommendedStyle": "ballad",
  "bpmSuggestion": 84,
  "explanation": "멜로디가 C장조 음계 위주이고 ..."
}
```
- 규칙 엔진이 이 형식으로 기본 결과를 만들고, LLM은 같은 형식으로 `explanation`(다듬은 설명)이나 `chords`(재추천)만 돌려줍니다.
- LLM 응답은 Zod로 검증하고, 실패하면 1회 재요청 후 규칙 엔진 결과를 그대로 씁니다.

### Supabase 테이블

**`projects`**

| 컬럼 | 타입 | 비고 |
|---|---|---|
| id | uuid (PK) | |
| user_id | uuid (FK → auth.users) | |
| title | text | |
| song | jsonb | SongState |
| is_public | boolean | 공유 링크용 (선택) |
| created_at / updated_at | timestamptz | |

**Storage 버킷**
- `recordings/{user_id}/{project_id}.webm` — 원본 녹음
- `exports/{user_id}/{project_id}.wav` — 내보낸 결과물 (선택 기능)

**RLS 정책**: 본인 `user_id`의 행만 읽기/쓰기, `is_public = true`인 행은 누구나 읽기 가능.

## 7. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 허밍 인식 정확도가 낮음 | 퀀타이즈 + 피아노롤 수동 수정으로 보완, 녹음 시 메트로놈 제공 |
| LLM 응답 형식 오류 | Zod 검증 → 재시도 → 규칙 엔진 결과 그대로 사용 |
| 규칙 엔진 분석의 한계 (관계조 혼동 등) | 장르 직접 선택으로 보완, 선택 기능(코드 진행 수동 수정, AI 재추천)으로 추가 보완 |
| 기존 곡을 흥얼거린 결과물의 저작권 문제 | 이용 안내에 명시하고, 사용자 본인의 허밍만 입력받음 |
| 반주가 어색하게 들림 | 장르 수를 줄이고 템플릿 품질에 집중, 샘플 악기 사용 |
| 브라우저 오디오 호환성 (특히 iOS Safari) | 사용자 클릭 후 AudioContext 시작, 데스크톱 Chrome을 기준 환경으로 명시 |
| 일정 지연 | 필수 기능 우선, 선택 기능은 MVP 완성 이후에만 착수 |
| LLM API 비용 · 정책 변화 | 기본 분석은 규칙 엔진이 처리하고 LLM은 설명 다듬기(선택 기능 시 재추천)에만 호출, 사용자당 호출 횟수 제한 |

## 8. 평가 · 시연 포인트

- 현장에서 청중 한 명의 허밍을 받아 **1~2분 안에 밴드곡으로 완성**하는 라이브 데모
